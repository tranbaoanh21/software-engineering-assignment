\newcommand{\IntegratedUseCase}[6]{%
  \subsubsection{#1 -- #2}
  \paragraph{Đặc tả Use Case và truy vết}
  \begin{sloppypar}Trình bày phiên bản cuối của đặc tả \texttt{#1}, bao gồm actor, mục tiêu, trigger, precondition, postcondition, main flow, alternative flow và exception flow. Các mã cần đối chiếu: #5.\end{sloppypar}
  \paragraph{Thiết kế giao diện}
  \begin{sloppypar}Trình bày UI mockup và ảnh giao diện hiện thực của các màn hình #3. Bao phủ happy path và các trạng thái loading, empty, validation, stale-data hoặc lỗi khi có liên quan.\end{sloppypar}
  \paragraph{Biểu đồ hoạt động}
  Trình bày \texttt{ACT-#1}; guard, nhánh lỗi và điểm kết thúc phải khớp đặc tả use case cùng business rule.
  \paragraph{Biểu đồ tuần tự}
  Trình bày \texttt{SEQ-#1}; actor, boundary, service, repository và external adapter phải phản ánh implementation cuối cùng.
  \paragraph{Biểu đồ trạng thái liên quan}
  \begin{sloppypar}Các state chart liên quan: #4. Đặt hình tại UC sở hữu chính; nếu đã xuất hiện trước đó thì dẫn chiếu số hình và giải thích transition do \texttt{#1} kích hoạt.\end{sloppypar}
  \paragraph{Biểu đồ lớp và đặc tả phương thức}
  Trình bày phần class diagram \texttt{CD-#6} liên quan đến \texttt{#1}; mô tả lớp, trách nhiệm, method/interface, input/output, lỗi, side effect và transaction boundary.
  \paragraph{Kiểm thử, hiện thực và demonstration}
  Trình bày \texttt{TC-#1} và \texttt{DEMO-#1}: dữ liệu kiểm thử, expected/actual result, evidence, ảnh giao diện chạy thật hoặc log/API. Phân biệt rõ nội dung đã hiện thực với nội dung mô phỏng.
}
