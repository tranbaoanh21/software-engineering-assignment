\newcommand{\BehaviorUseCase}[6]{%
  \subsubsection{#1 -- #2}
  \noindent\textbf{Baseline Phase 1:} \texttt{#1}. \textbf{Màn hình liên quan:} #3.\par
  \noindent\textbf{Truy vết yêu cầu:} #4.\par
  \noindent\textbf{State chart liên quan:}\par
  \noindent #5. State chart được đặt một lần ở phần mô hình trạng thái; tại đây chỉ dẫn chiếu để tránh lặp hình.\par
  \paragraph{Thiết kế giao diện}
  \begin{sloppypar}Trình bày các màn hình #3 thuộc bộ mockup #6, bao gồm trạng thái mặc định, loading, empty, validation, stale-data và lỗi có liên quan đến \texttt{#1}.\end{sloppypar}
  \paragraph{Biểu đồ tuần tự}
  Sơ đồ \texttt{SEQ-#1} giữ nguyên actor, trigger, main flow, alternative flow, exception flow và các external system đã khóa ở Phase 1.
  \paragraph{Biểu đồ hoạt động}
  Sơ đồ \texttt{ACT-#1} có start/end, action, decision/merge, guard và swimlane khi cần phân biệt trách nhiệm.
  \paragraph{Biểu đồ trạng thái liên quan}
  \begin{sloppypar}Dẫn chiếu các state chart #5 và giải thích transition do \texttt{#1} kích hoạt; không sao chép lại cùng một state chart.\end{sloppypar}
  \paragraph{Giải thích thiết kế}
  Nêu phạm vi luồng được mô hình hóa, các quyết định quan trọng, \texttt{BR-*}/\texttt{FR-*} chi phối và cách UI, sequence, activity và state chart khớp nhau. Không chép lại nguyên Use Case Specification.
}
